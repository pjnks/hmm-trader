1. Alpha Thesis

The Nasdaq 100 is fought over by armies of PhDs with co-located servers. A $50M micro-cap is fought over by retail traders and stale algorithms. The information asymmetry is the edge.

Grinold's Fundamental Law of Active Management: IR = IC × √Breadth. CITRINE's 0.90 confidence gate on 98 tickers produces ~7 entries/day. FLUORITE's relaxed alt-data funnel on 4,000 tickers produces 30–60 scored candidates and 5–12 positions — a 6.4× breadth multiplier. Even with lower per-signal IC, the information ratio can be higher.

This is not a traditional quant system. It is an Automated Analyst that reads thousands of filings, tracks insider behavior, maps supply chains, and monitors digital footprints — things a human analyst can do for 10 companies but not 4,000.

Critical Design Decision: Risk Manager, Not Shared Ranker

Pipeline B cannot wait for Pipeline A's end-of-day cross-sectional ranking. If an 8-K drops at 10:15 AM announcing an FDA approval, the alpha decays in seconds. Therefore:

  • Pipeline A goes through the cross-sectional ranker (buying the top basket at next-day open).
  • Pipeline B bypasses the ranker entirely. If LLM conviction >90, it immediately requests capital from the shared Portfolio Manager. As long as sector/exposure caps aren't breached, Pipeline B executes instantly.
  • Pipeline B overrides Pipeline A for the same ticker on the same day. An 8-K filed at 10:30am is strictly more informative than last night's alt-data scan. Fusion scoreboard has a last_updated timestamp; B events overwrite with a freshness bonus.

TIER 2 runs five independent signal modules. Each produces a 0–100 score per ticker.

A. Insider Cluster Detector (Form 4) Cost: $0 • You have this pipeline

You already ingest Form 4 data via src/alternative_data.py for BERYL/CITRINE. Enhancement: cluster detection — 2+ insiders buying within 72 hours = conviction multiplier. A CFO buying $200K of a $80M company is a 0.25% personal position — that's a screaming signal.

Why primary: Highest-conviction, lowest-cost signal in the entire system. On small caps, insider clusters are far more informative than on mega-caps. Insiders know their business better than any model.

B. Supply Chain Ripple Graph Cost: $0 • JSON adjacency list

JSON adjacency list mapping apex companies to their suppliers: NVDA → [TSM, AVGO, MRVL, ARM], AAPL → [AVGO, TSM, QCOM, HON]. ~500 edges covering NDX100 apex nodes to small-cap supply chain.

Screener logic: When an apex node gaps >3%, flag suppliers that haven't moved yet. Ripple window: 24–48h for large caps, 3–5 days for small caps (slower information propagation). Start simple with ~500 edges; no graph DB needed at this scale.

Data sources: 10-K "major customers" disclosures, Wikipedia supplier lists, FactSet public data.

C. Digital Footprint Tracker Cost: $0 • Free APIs

Detects slow divergences that events and filings miss. Three sub-signals:

  • Google Trends 90-day momentum (free API, 5 queries/min) — search interest acceleration for company/product names
  • App store rank delta — consumer-facing tickers (AAPL, AMZN, NFLX, META, gig-economy, fintech)
  • Job posting velocity (Indeed/LinkedIn) — expansion signal before it hits revenue

Why it works: By the time Q3 revenue is reported, that data is 3 months old. Digital footprints are real-time revenue proxies.

D. Event Tripwire Flags Cost: $0 • RSS + API

Cheap binary triggers for Pipeline B (intraday) and Pipeline A (overnight catch-up):

  • 8-K filed in last 24h — flag + download text for Tier 3 LLM
  • Volume > 3× 20-day avg — flag (something is happening)
  • Price gap > 5% on open — flag (news overnight)
  • Earnings in next 48h — flag (pre-position or avoid)

Pipeline B specific: SEC EDGAR live RSS feed listener. Fires within seconds of an 8-K filing. This is the primary trigger for the intraday sniper.

E. Sector Regime Context (HMM, adapted) Cost: $0 • Reuse existing

Run HMM on 13 sector ETFs: XLK, XLF, XLE, XLV, XLI, XLC, XLY, XLP, XLRE, XLB, XLU + IWM (small-cap index) + QQQ (tech benchmark). Each ticker inherits its sector's regime state.

Regime gate: BEAR sector = raise LLM conviction threshold from 70 → 90. Don't take alt-data long signals into adverse sector regimes. This is the filter that kills most alt-data strategies — they trade into bear markets and get crushed.

Implementation: Consume regime output from existing BERYL/CITRINE HMM infrastructure. Don't re-run the HMM — read their output files.

Pipeline B Variant: LLM Rapid Reflex (<5 seconds)

When Pipeline B fires on an 8-K, the LLM prompt is shorter and more decisive:

"You are an event-driven trading algorithm. Read this 8-K.

Answer: YES or NO, conviction 0-100, one-sentence reason."

Response time: ~3 seconds. If YES + conviction >90, proceed directly to execution via Portfolio Manager.

6a. Cross-Sectional Fusion Model (Pipeline A only)

TIER 4 uses a cross-sectional XGBoost trained on ALL tickers simultaneously. This solves the data sparsity problem — individual micro-caps may have sparse history, but 4,000 tickers × 252 days = 1M+ training rows per year.

LLM Backtesting Reality

Tier 3 LLM scores are inherently forward-only. You cannot retroactively run Claude on historical 8-Ks and pretend it's point-in-time — the model's training data includes knowledge of what happened after those filings. The backtest covers Tiers 1–2 only. Tier 3 conviction enters the model as a feature only after the shadow period produces enough labeled data (60–90 days).

Pipeline B Execution (Sniper Mode)

Pipeline B bypasses the cross-sectional ranker. When the LLM Rapid Reflex returns conviction >90:

  1. Check with Portfolio Manager: sector cap not breached? Total exposure not maxed?
  2. Ping Polygon for current bid/ask spread — if spread >1.5%, abort.
  3. If stock hasn't already halted or gapped >15%, execute aggressive limit order (mid + 0.25%).
  4. Goal: fill within 15 seconds of 8-K publication. You are racing the rest of the market reading that document.

11. Identified Gaps & Mitigations

Five practical gaps identified during architecture review. Each has a concrete fix.

Gap 1: VM Can't Run Pipeline B

Oracle VM is 1 OCPU / 1GB RAM, already at ~500MB with BERYL + CITRINE. Adding Pipeline B risks OOM-killing live services — you fought this war with DIAMOND (14 OOM kills, Sprint 12).

Fix: Run Pipeline B on Mac during market hours. VM stays as execution relay. Optional: spin up a second free-tier Oracle VM dedicated to Pipeline B.

Gap 2: No Backtest for LLM Signals

Can't retroactively score historical 8-Ks with Claude — model training data includes future knowledge. LLM Tier 3 is inherently forward-only.

Fix: Backtest Tiers 1–2 only. Track Tier 3 in shadow mode for 60–90 days. XGBoost trains on Tier 1–2 features initially; Tier 3 conviction added only after shadow calibration. Same pattern as CITRINE shadow tracker.

Gap 3: Cold Start / Chicken-and-Egg

Fusion model needs training data, but alt-data features don't exist historically. Can't train until you've been collecting for months.

Fix: Three-stage cold start (rule-based → shadow ML → ML takes over only if it beats rules). Same as DIAMOND's CTM_ENABLED=false pattern. See Tier 4 section.

Gap 4: Pipeline A/B Conflict Resolution

Pipeline A says "ACME scored 45 last night" but Pipeline B says "ACME just filed an 8-K with a $40M contract win today." Which signal wins?

Fix: Pipeline B always overrides Pipeline A same-day. Fusion scoreboard has last_updated timestamp; B events overwrite with freshness bonus. Also: B positions feed back into A's next nightly scan (don't double-up).

Gap 5: Codebase Location

FLUORITE is architecturally different (alt-data-driven, not HMM-driven) but shares infrastructure with trading-core.

Fix: New standalone repo ~/Documents/quant/fluorite/ with its own CLAUDE.md. Imports shared modules from trading-core for execution (broker, notifier, kill-switch). Daily batch and event watcher are FLUORITE-specific.
